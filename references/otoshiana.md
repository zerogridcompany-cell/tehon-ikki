# 落とし穴（一度踏んだ物・段ごと）

## 道具・回し方
- 🔴 ECC のマスクは「入力の絵」の大きさ。画面の大きさで渡すと毎回エラー→黙って飲んで初めの位置のまま（r2 10/25：43枚全部で ECC が効いてなかった）。失敗は表に出す
- 🔴 土台 base.mp4 は毎回組み直す（r2：古いままでテレビ5カットが真っ黒）→ run.sh render が毎回 assemble する
- 🔴 書き出しは `--gl=angle`（無いと three.js の場面で WebGL が作れず落ちる）
- 🔴 `while read` の中の ffmpeg は `-nostdin`（行を食ってフォルダ名が崩れる）
- 🔴 `codex exec` に `--full-auto` は無い・`-i 絵` は後ろの文を食う＝付けん（task.md に「参照画像は ref.png」と書く）
- 🔴 zsh の `set -- $p` は分割されん＝bash で回すか `${=p}`
- 🔴 待ち合わせに `pgrep -f` を使わん（自分に当たる）。重い作業の数は「python／node の本体の命令の文」で数える（ps の名前の欄は16字で切れる）
- Remotion のブラウザ側では process.env が読めん＝数字は直接書く
- Air の homebrew の python3 には numpy・cv2 が無い時がある（51）＝/usr/bin/python3
- mini も Air も YouTube に止められる＝1本ごと10秒・ブラウザのログイン（YT_COOKIES=chrome）・同時に2台で叩かん
- 1時間の動画の目印を全部保存すると mini が満杯で落ちる＝uint8・使わん分は消す。探し同士は置き場（--cand）を分ける

## 測り・判定
- 🔴 探しの「当たり」は目で見る（r2 3周目：目印 9〜13点の当たり4つが全部外れ）。見込みの当たり率も目で確かめた物だけで数える
- 🔴 ぼかすほど SSIM は上がる＝最良から 0.01 以内で一番小さい σ
- 🔴 乱数（粒・砂嵐・札の雨）は手本に合わせるほど画素の SSIM は下がる＝動きの数字と両方のコストで決める
- 🔴 色・明るさを変えたら切り替えの強さも変わる＝切り替え合わせは最後
- 🔴 白い地の絵で「白い画素＝字幕」と探すと地が全部消える＝字幕は caps.json の箱で外す
- 🔴 SVG の feComposite で光を足すと Python の当てと合わん＝σ ごとの層を plus-lighter で
- 🔴 書体は読み終わるまで描かせん（delayRender）
- 🔴 書体の高さを括弧など書体ごとに長さの違う字で測らん（数字で測る）・測る窓は行の間隔より狭く
- 🔴 ぼかしの前に粒を足すと消える
- 3D の動き（見る角度が変わる）を平面の変形で追うと床がずれて悪くなる＝「初めの位置／真ん中で固定」と比べて選ぶ
- 手本の字の高さは出揃った後のコマで測る（途中だと大きさを誤る・51）
- ffmpeg -ss (f+0.5)/fps は f+1 から読む（51）＝コマ番号で読むなら select=eq(n,f)
