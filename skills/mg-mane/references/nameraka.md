# 滑らか（なめらか）＝手本の動きを「連続した曲線」で写す道具と決まり（11/3 tehonN v4）

依頼者 11/3「カクカクしてる所がある。滑らか感は絶対に習得して。最初速くてあとゆっくりの動きはキーフレームで設定できるから詰めて」。
v3→v4 で **止まり 22→3・余計 41→4・ギザ比 全区間 ≤1.17・動きの波 0.957→0.963**（実例＝`~/research/tehon-me/tehonN/滑らか_報告.md`）。

## 道具（scripts/・assets/・/usr/bin/python3・numpy と cv2 だけ）
| 道具 | 何をする | 使い方 |
|---|---|---|
| `scripts/nameraka.py` | 光の流れで「動いとる画素だけの速さ v(t)」を手本とうちで比べる（止まり・余計・速さの波・ギザ・折れ） | `nameraka.py <手本> <うち> --out <置き場>` |
| `scripts/kiseki.py` | 手本の 1 つの物の道を 1 コマずつサブピクセルで（flow＝DIS の流れの中央値＋アフィンで横・縦の大きさ／box＝色や明るさの箱）。枠は物に追いつく | `kiseki.py <手本> --roi x,y,w,h --from F0 --to F1 [--mode box --mask orange] --out <json>`（絵 .jpg も出る） |
| `scripts/ease_fit.py` | 道を「動く／止まる」に割り、区間ごとに bezier・expo_out・pow_out/in/inout・back_out・spring(w,z,v0)・bounce・linear を当てて一番合う物（速さの相関 ≥0.97 の中で RMS 最小）→ keys.json＋絵（位置と速さの 2 段） | `ease_fit.py <kiseki.json> --axis y --warp 9 [--seg "a-b,c-d"] --out <keys.json>` |
| `assets/ease.ts` | Remotion で keys.json を連続の関数として評価（`kfAt`・`vel`・`tau`・`springT`・`tw`・`mblur`・`sgT`）。ease_fit の評価と 1e-4px で一致（確かめ済み） | `proj/src/<場面>/` に写して import |

- kiseki の flow は大きい物・カメラ（板の流し 549 で前後の 2.04 倍を拾えた）に強い。小さい物・字は `--mode box` か、連結成分の箱を自分で当てる方が確か（tehonN の字・n・つまみ・玉は箱で測った）
- ease_fit の自動の割りは「同じ向きに 2 回加速する」動きを 1 本にしがち＝`--seg` で手で割る。カメラの込み入った道（板の射影）は曲線にせず、測った表を τ でならす方が近い

## 決まり（tehonN で数字で確かめた物）
1. **手本の時間 τ を先に測る**：tehonN は `τ(f)=f+floor(f/9)`（9 の倍数のコマが 2 歩＝前後の 1.63 倍・板の流しで 2.04 倍）。曲線は τ で当てて τ(f) で評価する＝手本の「飛び」もそのまま写る。見分け方＝nameraka.json の v を f%9（や他の周期）で束ねて前後との比の中央値を見る
2. **手で置いた鍵は τ の上の単調 3 次（PCHIP）でつなぐ**：線形は鍵ごとに折れ、smoothstep は鍵ごとに速さ 0（＝止まり）。PCHIP は行き過ぎず、端の速さ 0
3. **コマごとの鍵（毎コマに値）は τ の 2 歩を消す**：9 の倍数のコマが 2 歩にならん（tehonN 675 の山 12.2 が 5.7）→ τ の式（`u=(T(f)-T(a))/(T(b)-T(a))`）で書く
4. **ブレ＝手本は 1 コマ分のシャッター**：細い再生の棒が動くと 16px 幅のうすい帯（暗さ 1/6）＝σ ≈ 0.28〜0.29×1 コマで動いた長さ。`mblur(vx, vy, 0.28)` を向きつきで。拡大縮小の中の物は σ を局所の倍率で割る（CSS/SVG のフィルタは変形の前にかかる）
5. **フィルタの落とし穴**
   - 縦の `<line>` に `x="-800%"` の objectBoundingBox のフィルタ＝箱の幅 0 で線が消える（tehonN 310 で再生の棒が消えとった）→ `filterUnits="userSpaceOnUse"` で x,y,w,h を書く
   - しきい（0.35px）でフィルタを付けたり外したりせん：その 1 コマだけ字の描き方が変わって跳ぶ（747 の余計な「切り替え」）→ 付けっぱなし・σ は連続（ease.ts の floor 既定 0）
6. **見た目は変えず、時間と曲線だけ手本**：手本の測り（箱の幅・中心）を 0..1 に正規化して、うちの v3 の端の値（大きさ・置き場）の間に写す（形の場面・n の道）。大きさまで手本に寄せると見た目が変わる
7. **測った表とカメラは同じ物でそろえる**：玉の世界の座標を「生のカメラ」で出したあと、カメラだけ中央値に替えると玉が ±7px ぶれる（tehonN v3 の 336〜342）。カメラは手本のはっきり写る物（玉）から 1 つの硬いカメラとして作り、玉は世界で止める
8. **作りで補った区間は手本の割合で**：217〜223 のカメラを smoothstep で補うと手本より先に引いて 224 で 60px 戻った＝手本の玉の中心の割合 u(f) で端の値の間をつなぐ
9. **重ねの入れ替え（crossfade）は不透明度の谷を作らん**：消える物は出る物が出切ってから消す（板の 456〜457 が白っぽく抜けた）
10. **字の揺れ・入り・散りは手本の箱で**：MOTION の字は 1 字ずつの中心・下の縁・幅を連結成分で測り、うちのカメラ（MCAM）で世界へ戻して足す（55〜71 の止まりが消えた・T は 44 まで落ち続ける・O は 36 で跳ねる）。1 コマで飛んで消える散り（T 107.5・O2 109・M 109.5・I と N 114.5）は 4〜5 コマかけると余計に動く
11. **回り（rotateX）の速さ**：90° と 270° のくぼみの間のコマ数で測る（tehonN は 6 コマ＝30°/コマ一定・12 コマで 1 回転）。smoothstep 10 コマは山で 54°/コマ＝2 倍動く
12. **札の数字（spring(180,12) 等）が画面にあれば、その数で当ててみる**：ω=√180/60=0.2236/コマ・ζ=12/(2√180)=0.447 で速さの相関 0.992（自由に当てると ω0.2258 ζ0.4773）
13. **止めの間も動く**：手本の寄り・板は着いた後も 1〜3px/コマでゆっくり収まる（編集画面のカメラ 243〜262・名前の n 738〜760）。中央値で止めると止まりになる

## nameraka の数字の読み方（だまされん所）
- 「止まり」は 480 幅の差 0.25 の線で決まる。手本は圧縮の粒で線を越えるので、うちが全解像度で 0.3 変わっとっても「止まり」に数えられる事がある（tehonN 305・390・391）。止まりが出たら、まず全解像度のコマの差を手本と並べる
- 部分の試し（`tools/v4_part.sh a b`＝コマ範囲だけ書き出して手本の同じ範囲と比べる・10〜20 秒）と全体の書き出しでは、手本を切り出し直す分だけ「同じコマ」の判定がずれる。最後は全体で測る
- 4 コマ程度の短い区間の速さの波は数が少なくて当てにならん（tehonN 204-207）

## 終わりの暗くなり（明るさの表）と色の形式
- 手本の明るさを 1 コマずつ測った表には手本の圧縮のゆれ（-0.006／-0.016 が交互）が入っとる。`--color-space=bt709 --pixel-format=yuv420p` で書き出すと、このゆれが 2 倍に出る（変わらんコマ・4 段跳ぶコマ）＝明るさのカクつき・816 が「切り替え」に見えた（v3 の作りで書き出しても同じ＝色の形式のせい）
- 滑らかを取るならコマの上でならす（歩幅がそろう）。その代わり hakaru の「名前」区間の波は手本の圧縮のゆれと合わんようになって下がる（0.843→0.594）。τ でならすと 9 の倍数の 2 歩で跳ぶ・生と半分ずつは半端（相関 0.44）

## jp4（手本B・幾何の平面・20fps）v3 で分かった事（11/3・実例＝`~/research/tehon-me/jp4/滑らか_報告.md`）
v2→v3＝止まり 62→2・余計 9→1・同じコマ 263→216（手本 195）・hakaru 動きの波 0.882→0.917・速さの波（切り替えのコマを抜く）46-88 0.850→0.950／172-197 −0.302→0.818／307-333 0.206→0.734
1. **手本の時間は「止まる」型もある**：18fps で作って 20fps＝10 コマに 1 回前のコマと同じ（tehonN の「飛ぶ」型 τ=f+floor(f/9) の逆）。止めのコマは前と同じ値・その間は **10/9 の等しい歩幅**（jp4 `JP4.tsx` の `TAU`・`tools/v3_tau.py`）。「止めのコマを前のコマにする」だけだと次のコマが 2 歩ぶん跳ぶ（jp4 v2 187：差 0.62 vs 前後 0.38）。網の位相は場面（クリップ）ごとに違う（jp4＝太陽の形 n%10=1・135〜155 は 5・176〜346 は 6・59〜126 は網なし）＝全解像度のコマの差（<0.05）を場面ごとに見て決める。色だけ毎コマ変わって形は止まる場面もある（太陽 21・31）
2. **手本の縁のぼけが 0 ならブレは足さん**（jp4 は 173・230・294 の速いコマでも縁がくっきり＝mblur 0）
3. **測りの型**：色の塊の箱（Lab ΔE<14 の画素の 0.5〜99.5% の箱と重心・`jp4/tools/v3_measure.py`）を場面ごとに。カメラ（全体の流れ）と回りの向きは kiseki の flow（大きい枠・`--margin 0`）。測った道は手本の時間 t に直してから ease_fit（`jp4/tools/v3_fit.py`）
4. **ease_fit の読み方**：等速のゆっくりした流れは速さの相関が出ん（一定＋ゆれ＝vcorr ≈0）→ RMS で見て linear に（bezier の変な形は速さが途中で山・谷になる）
5. **混ざりに気をつける**：赤いドームの「右へ流れ」に見えたのは赤い扇の上の端が枠に入ったから（ドームの中の丸は真ん中のまま）＝流れの向きは中の物で確かめる。回る向き＝kiseki の r が負は反時計回り（y 下向き）・芯の下で dx>0 も反時計回り。16° おきのとげは ±8° で向きが読めん
6. **nameraka の数字の読み方（追加）**
   - 切り替えのコマ（大きな入れ替わり）の v は書き出しの粒で大きく揺れる（jp4 285：v2 と v3 で絵の差 0.5 なのに v 16.6 と 49.9）＝区間の速さの波はここに引っぱられる。切り替えのコマを抜いた波も並べる（`jp4/tools/v3_wave_cut.py`＝両方の 480 幅の差が 8 以下のコマだけ）
   - 色だけ変わる場面（色が濃くなる）の手本の v 0.6 は光の流れが色の変わりを拾った物で、形の動き（1.3 px/コマ）は流れの線 0.5 の下＝うちが同じ色の曲線・同じ形の動きでも拾われん（jp4 23-42 の波 0.1）
   - 止まりの線（480 幅の差 0.25）すれすれのコマは書き出しごとに入れ替わる（jp4 131：0.250 で通り、次は 0.249 で止まり）
   - 大きな物が消えた次のコマの手本の v は書き出しの残り揺れのこともある（jp4 333：柱の所は地と ΔE 0.6〜3＝残りは無い）＝写さん（薄い残りを足すと目に見えた）
7. kiseki.py：窓の切り出しを連続の配列に直した（幅いっぱいでない窓で DIS が `I0.isContinuous()` で落ちた）

## exp1（手本F・Apple 風 UI）v3 で分かった事（11/3・実例＝~/research/tehon-me/exp1/滑らか_報告.md）
止まり 299→179・同じコマ 882→744（手本 678）・動きの波 0.971→0.984・切り替え 4/4 余計 0・ΔE 0.76→0.75。道具＝`kiseki.py --mode edge`（新）・`kiseki_ecc.py`（新）
1. **箱を画素に吸い付かせん**：CSS の left/top/width/height は Chrome が箱の縁を整数の画素に丸める＝ゆっくり動く所（0.3〜1.5px/コマ）で 3〜4 コマに 1px の階段＝間が「同じコマ」＝止まり。置き場は `translate3d` の小数、大きさは整数の箱＋残りの拡大（`scale(w/round(w), h/round(h))`）。書き出しを edge で測ると表と 0.1〜0.2px で一致した
2. **`kiseki.py --mode edge`**：等倍で物の縁をサブピクセルで（覆い a＝1−|画素−物の色|/|地−物の色| を真ん中の帯の各行・各列で外から 0.5 を越える所）。黒い窓・白い欄・吹き出し・黒い絵で 0.1px のゆれ。白い札×明るい地（差 8 段）と影は取れん（そこは中の黒い絵で札の動きを測る）。--follow で枠が広がって別の物を拾う時は固定の枠で
3. **Apple 風の UI は「止まって見えて動き続ける」**：窓は着いた後もバネで息をし（幅 741→735→778→762）、中身は窓の角に付いて一緒に動く（印は左の縁＋88.6px で一定）。中身を真ん中からの固定の位置にすると縁だけが動いて差が足りん＝止まり
4. **ease_fit の自動の割りは息をする所を「止」にする**（s3 の cy は全部止）＝止まりそのもの。こういう所は測った表を SG（前後 2〜3・2 次）でならす。はっきりした 1 本の動き（語の縦のバネ・落ちる語）は ease_fit の spring がよく当たる（相関 0.98〜0.995）
5. **画面の外へ出る寄りは ECC で基準のコマへ直接重ねる**（`kiseki_ecc.py`）。流れをつないだカメラは速い寄りで 2 コマに 5% ずれた
6. **nameraka の v は暗い・白い無地の上で暴れる**（Farneback が無地へ流れを広げる）：手本を crf10 で再圧縮しただけで 401：34.7→4.4・403：2.0→28.4。同じ絵（差 平均 0.04〜0.1）を書き出し直しただけで 598：5.3→32.5。その区間は 1 コマの差 d を手本と並べて「動きが合っとるか」を確かめる（exp1 の s5・s7 は d が手本と同じ＝止まりは物差しのゆれ）
7. **周りを滑らかにすると、元からある 1 コマの入れ替え（札の入れ替え・背景の色の切り替えと重なる所）が hakaru の「切り替え」（前後 2 コマの 1.8 倍）に見えてくる**＝直した後は必ず hakaru の切り替えを v 前と比べる。直す時は入れ替えの前後の差を残す（v2 の値へ混ぜる）
8. **書き出しの回数を使い切った後の直し**：鍵コマ（`ffprobe -show_entries frame=key_frame`）の間の塊だけ部分書き出しし、元の動画を `-f segment -segment_frames` で鍵コマで切って `concat -c copy` で差し替える＝再圧縮なし・直さん所は 1 画素も同じ（exp1 の 831〜1214・1315〜1535）
